# Phase 2 of 16: Scroll engine, WebGL stage, texture manager and chrome

You are building orange.io, a scroll story drawn by one raw WebGL canvas. Phase 1 set up the app, fonts, tokens, copy and the art manifest. This phase builds the engine every later phase runs on. Nothing in this phase is a scene.

## Rules

- **Source of truth:** `docs/STORY.md`, `docs/MOTION-RULES.md` (read the whole file; the scroll smoothing section is implemented here), `docs/PAINTINGS.md` (asset kinds and tiers). Read `src/content/art.ts` and `src/content/copy.ts` from phase 1.
- **One stage, one canvas:** raw WebGL 1 with the `OES_standard_derivatives` extension when available. No Three.js, no React Three Fiber, no GSAP, no Lenis.
- **Scroll is the clock:** everything is a pure function of smoothed `p`; reversible; nothing keyed to raw `scrollY`; no React state per frame. The stage is one client component that owns a `requestAnimationFrame` loop and talks to React only through refs and a tiny subscribe API for DOM layers.
- **Copy** from `src/content/copy.ts` only. **Art** through `src/content/art.ts` only.
- **Deploy contract:** `npm run lint`, `npm run typecheck`, `npm run build` stay green; `npm start` serves on 3000.
- **Git:** do not commit or push; the skill does.
- **Finish** with 3 to 6 lines: what now exists, what is still a placeholder, and anything you could not verify.

## Task

1. **Stage markup** in `src/stage/Stage.tsx`: `<section class="stage">` about 60 viewport heights tall; inside it a `position: sticky` `.pin` filling the viewport with one `<canvas class="gl">`, the hidden hero `<video>` element (muted, loop, playsInline, preload auto, poster), and a `.layers` div for DOM text. `html, body { height: 100% }`; the body never scrolls horizontally.
2. **Scroll clock** in `src/stage/scroll.ts`: exactly the smoothing in `docs/MOTION-RULES.md`: wheel intercepted (not with `ctrlKey`), `target`/`current`, `current += (target - current) * (1 - exp(-dt/180ms))`, snap under 0.08px, `velocity`, native scroll with a 60 ms constant on `pointer: coarse` or `prefers-reduced-motion`; keyboard and anchor jumps set `target`. Exposes `p` (0..1), `vel` (px per frame), `dt`, and `reduced`. Scroll restoration on reload lands on the same `p` without playing the intro.
3. **Script** in `src/stage/script.ts`: the named segments of `docs/STORY.md` with their `p` ranges as the single source of ranges (`hero`, `bridge`, `model`, `split`, `work`, `parchment`, `sheet`, `drawing`, `panel`, `close`, `coda`, `matchcut`, `questions`, `moire`, `application`, `rise`, `finale`), plus helpers `local(segment, p)` (0..1 inside a segment, clamped), `active(p)` and `nearby(p, margin)` for gating work. No component may hardcode a range.
4. **GL core** in `src/stage/gl/`: context creation (alpha false, antialias false, high-performance), program builder with shader-compile error reporting to the console and a `?nogl` fallback that hides the canvas, a uniform registry, a single full-screen triangle, resize with `devicePixelRatio` capped at 2 and at 3.4 Mpx total, and a `?hud` overlay (p, segment, local t, frame ms, texture uploads per second).
5. **GLSL library** `src/stage/gl/lib.glsl.ts` exported as a string prepended to every fragment shader: `hash`, `vnoise`, `fbm` (octave count as a uniform so phones can drop to 2 on texture fields while motion fields keep 4), `bayer4`, `smear5(sampler, uv, dir, len)`, `blur(sampler, uv, radius)` (9 taps), `cover(uv, texSize, pan, zoom)` fitting a 16:9 source to any viewport with a per-shot pan and zoom, and `uncover(point, texSize, pan, zoom)` (its exact inverse, so a point in a painting maps to the screen at any viewport), plus a `dollyAbout(uv, o, s)` helper. Include a short comment on each, and a `/stage-test` dev page that draws a labelled checkerboard through `cover()` and marks three `uncover()` points so the mapping can be verified by eye.
6. **Texture manager** `src/stage/gl/textures.ts`: image stills (tier chosen from viewport width: 1440 or 768), video loops (upload each frame with `texImage2D` only while the loop's segment is near; pause otherwise), and frame sequences: read `manifest.json`, `aim(frame)` decodes around the aimed frame in both directions with a small worker pool and `createImageBitmap`, `near(frame)` returns the nearest decoded frame so the shader never gets a blank, and uploads happen only when the chosen frame changes. Memory: keep at most 24 decoded frames per sequence.
7. **Pass manager** `src/stage/gl/passes.ts`: one fragment shader per chapter group is fine, but the stage draws exactly one full-screen pass per frame, chosen by `script.active(p)`, with the shared uniforms (`uRes`, `uDpr`, `uTime`, `uP`, `uT` local, `uVel`, `uMouse`, `uStill`, `uOctaves`) set once. Each pass declares which textures it needs so the manager can preload the next segment's assets.
8. **Chrome** in `src/stage/Chrome.tsx`: the hairline frame (left and right verticals, top rule, mid rule, star mark), the Orange mark and grid menu button top-left, the Apply pill top-right (scrolls to the application segment by setting the scroll target), the left rail with the four chapter labels switching with `p`, and the bottom-right percentage; all from `copy.ts`, all positioned by the phase 1 layout tokens, all readable over the hero (milk on sky) and the sheet (ink on paper), switching colour by segment.
9. **Pointer and breath:** `uMouse` from the pointer with the rest-state smoothing in `docs/MOTION-RULES.md`; `uStill = 1` under reduced motion.
10. The home page mounts the stage with one placeholder pass that fills the canvas with `--sky` and draws the `uncover()` test marks, so `npm run build` passes and `/` renders. Verify lint, typecheck, build and that scrolling reports `p` in the HUD.
